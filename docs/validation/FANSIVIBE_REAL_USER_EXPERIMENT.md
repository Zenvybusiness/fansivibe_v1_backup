# Fansivibe Real User Experiment

## Section 12 — Real User Experiment

| Element | Definition |
|---|---|
| **HYPOTHESIS** | If a user receives a personalized hairstyle recommendation with a grounded explanation and confidence score, then at least 10% of users will tap "Save Style" to save the recommendation to their profile. This tests whether the core value mechanism (recommendation → user decision → save) resonates with real users. |
| **TARGET USER** | Mobile app user who navigates to the hairstyle feature (Stylist → Hairstyle or Daily Look CTA on Home). Must have front-facing camera access (phone). No demographic restrictions — the narrowest justified segment from Section 4. "Demographic assumption — requires validation." |
| **USER SITUATION** | User opens the Fansivibe app and decides to get a hairstyle recommendation. Entry point: Home screen's "Daily Look" CTA → hairstyle, or Stylist tab → Hairstyle. User is making or considering a hairstyle decision. |
| **TRIGGER** | User taps "Scan My Hairstyle" or equivalent CTA to start the face scan flow. The flow begins at `FaceScanScreen` → camera/image picker → `faceProfileRef` submission. |
| **INTERVENTION** | Complete hairstyle value loop: (1) User takes face scan, (2) Backend decision engine (7-stage rules pipeline) analyzes and generates personalized recommendation, (3) Recommendation displays on `HairstyleResultScreen` with: style name, match score, grounded explanation ("This style may create a more balanced silhouette for your face shape"), confidence score in [0,1], `needs_more_data` flag, "Save Style" CTA, alternatives. |
| **EXPECTED BEHAVIOR** | User sees the recommendation screen with all visual elements (style, explanation, confidence). User either taps "Save Style" or dismisses/navigates away. If user taps save, the `Idempotency-Key`-protected `POST /v1/looks/saved` is committed via TRX-3 with `look_saved` signal. |
| **EXPECTED STATE CHANGE** | - **If user saves**: `look_saved` learning signal committed to `learning_signals` table (TRX-3 atomic with `saved_looks` insert); saved style appears in `SavedLooksScreen` on next profile visit. <br> - **If user dismisses**: No signal committed; user returns to main app shell without save. |
| **EXPECTED OUTCOME** | Data on whether the core value mechanism works with real users. Primary metric measures save conversion; secondary metrics reveal where users drop off and why. |
| **PRIMARY METRIC** | **Save conversion rate** = (Number of users who tap "Save Style") / (Number of users who receive a hairstyle recommendation). This directly tests whether the core mechanism (recommendation → user decision → save) works. |
| **SECONDARY METRICS** | 1. **Flow completion rate** = users who complete the full scan→result→save/dismiss sequence / total who started <br> 2. **Average confidence score of saved recommendations** vs. unsaved <br> 3. **Drop-off point** in the flow (scan failure, poll timeout, result screen, before save button) <br> 4. **First-session completion** = users who finish the full hairstyle flow in their first session <br> 5. **Explanation visibility** (if analytics allow — whether the explanation section is visible/scrolled) |
| **SUCCESS THRESHOLD** | **≥10% save conversion rate**. Rationale: With no prior user data, 10% indicates at least some users find the recommendation valuable enough to save. Below this, the mechanism may not resonate. (Power analysis: 200 users minimum; if true rate is 20%, 200 users gives 80% power to detect at 5% significance.) |
| **FAILURE THRESHOLD** | **<5% save conversion rate**. Rationale: Indicates the core mechanism doesn't resonate with users in its current form. May indicate explanation/conidence not clear, users don't have immediate need, or trust issues. (With 100 users, observing 0 saves gives 95% confidence true rate <3.7% — Clopper-Pearson exact interval.) |
| **CONFOUNDERS** | - User's immediate need for a hairstyle change at that moment <br> - Trust in app recommendations (new app, unknown brand) <br> - Camera quality/face scan success/failure <br> - User's existing hairstyle satisfaction <br> - Time of day / mood <br> - First-time vs. returning user <br> - App version/known bugs <br> - Cultural/individual style preferences not covered by 4 catalog looks |
| **SAMPLE SIZE RATIONALE** | Minimum 200 completed hairstyle sessions to achieve statistical power. <br> Power calculation: To detect a 10% conversion rate vs. 5% baseline with 80% power at α=0.05, need ~400 users. For a more conservative estimate, 500 users would provide robust data. <br> - 0/200 saves → true rate <1.9% (95% CI) <br> - 20/200 saves → true rate 8.3-14.6% (95% CI) <br> - 50/200 saves → true rate 30.5-40.5% (95% CI) |
| **TEST DURATION** | 2-4 weeks depending on user acquisition rate, aiming for minimum 200 completed hairstyle sessions. Since this is an internal app, testing with available beta testers or a launch cohort. If 200 sessions not achieved in 4 weeks, extend or report as-inconclusive with available data. |
