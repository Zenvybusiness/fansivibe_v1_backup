## 1. Identified Operational Realities & Mitigations

### 1.1 Presigned Media Expiration (15-Minute Window)
- **Risk:** Presigned GET URLs generated by backend object storage expire after 900 seconds (15 minutes). If a user leaves the `SavedLookDetailsScreen` open for longer than 15 minutes and the device evicts the image from cache, an uncached image reload would fail.
- **Current Mitigation:**
  - `WardrobeCacheManager` uses `cached_network_image` with local disk caching keyed by URL base, preserving thumbnails on device.
  - Re-entering the screen or pulling to refresh calls `getSavedLook` or `listSavedLooks`, immediately generating fresh authorized presigned URLs.
  - Image failure degrades gracefully to category fallback icons via `WardrobeItemImage`.

### 1.2 Completely Archived Ensembles
- **Risk:** If a user deletes all garments comprising a saved look from their wardrobe over time, none of the pieces remain in active inventory.
- **Handling & Mitigation:**
  - The ensemble remains 100% visible in `SavedLooksScreen` and `SavedLookDetailsScreen`, showing snapshot fallbacks and "Archived piece (no longer in wardrobe)" notices.
  - Tapping "Log Wear Today" on an all-archived ensemble shows a clear, respectful notification: *"Cannot log wear: all ensemble pieces have been archived."*
  - The wear API is never called with invalid or nonexistent IDs.
  - Users can safely delete the saved look if they no longer wish to retain it.

### 1.3 Database Revision Baseline (0032 vs 0036 Head)
- **Risk:** Database remains at revision `0032` while the codebase contains migration scripts up to `0036`.
- **Handling & Mitigation:**
  - P1-2 strictly operates within the existing `saved_outfits` (JSONB snapshot) and `wardrobe_items` tables without any schema alterations.
  - As established in `DEBT_01_DATABASE_MIGRATION_READINESS_AUDIT.md`, upgrading revisions `0033` through `0036` should be conducted as a dedicated, standalone maintenance task rather than bundled into feature milestones.

## 2. Deferred Scope Explicitly Preserved

The following items were excluded from Stage 2 P1-2 by contract and remain safely deferred to their authorized milestones:
- **P1-3:** Weather-aware recommendation engine and live weather context.
- **P2-1:** Preference learning and implicit affinity feedback loops.
- **P2-2:** Batch wardrobe ingestion and automated tagging.
- **P2-3:** Virtual try-on (VTON) generation.
- **Commerce / Subscriptions / Customer Support:** Unrelated systems were completely untouched.
